# 材料脱敏工具（redact.py）

面向诉讼材料的批量脱敏脚本。支持 Word、Excel、PDF、图片与扫描件，保留原始目录结构，**不修改源文件**。

> **定位：辅助脱敏。** 姓名、地址（以及启用后的企业/机构名称）依赖上下文与结构特征识别，存在漏检和误检；扫描件依赖 OCR，存在识别误差。**所有输出在对外使用前必须逐份人工复核。**

---

## 一、目录结构

```
D:\claudedata\.claude\script\
├── .venv-redact\     虚拟环境（依赖装在 D 盘，约 330MB）
├── redact.py         主脚本
├── redact.bat        启动器（可拖拽文件/文件夹，默认保留企业名称）
├── redact_companies.bat  启动器（拖拽即额外脱敏企业名称）
├── README.md         本说明
└── _selftest\        自测样本与输出（虚构数据，可整体删除）
```

Python 解释器仍在 C 盘（3.11.9），`.venv-redact` 只承载 PyMuPDF、RapidOCR 等依赖，不影响系统全局环境。删除 `.venv-redact` 即可完全卸载。

## 二、三种用法

### 1. 拖拽（最省事）

把**一个或多个**文件/文件夹直接拖到 `redact.bat` 的图标上，或双击 `redact.bat` 后按提示输入路径。

- 拖多个文件：一次全部处理，共用同一个输出目录；同名文件自动加 `_1` 后缀。
- 拖文件夹：递归处理，保留原目录结构；一次拖多个文件夹时，以文件夹名作为输出的一级目录。
- 输出默认生成在第一个输入的旁边（文件 → 其所在文件夹；文件夹 → 文件夹内部），目录名为 `redacted_时间戳`。
- 批量处理时自动跳过名为 `redacted_*` 的目录，避免把上一次的脱敏件再处理一遍。

> 若拖拽后窗口一闪而过或没有任何处理记录，请改用命令行方式（见下），这样报错信息会保留在窗口里。

**需要脱敏企业名称时**，把文件拖到 `redact_companies.bat`，等价于加 `--redact-companies`；普通 `redact.bat` 默认不脱敏公司、律所等名称。

### 2. 命令行

```bat
cd /d D:\claudedata\.claude\script

:: 整批处理
redact.bat D:\案件\材料 -o D:\案件\材料_脱敏

:: 先预检，不生成文件
redact.bat D:\案件\材料 --dry-run

:: 只处理身份证和手机号
redact.bat D:\案件\材料 --categories id_card,phone

:: 需要脱敏企业名称时（默认保留）
redact.bat D:\案件\材料 --redact-companies

:: 全遮蔽 / 保留首尾
redact.bat D:\案件\材料 --mode star
redact.bat D:\案件\材料 --mode keep
```

### 3. 直接调用虚拟环境

```bat
.venv-redact\Scripts\python.exe redact.py D:\案件\材料 -o D:\案件\材料_脱敏
```

## 三、参数

| 参数 | 说明 |
|---|---|
| `input` | 待处理文件或目录，可一次传多个（必填至少一个） |
| `-o, --output` | 输出目录；默认在第一个输入旁边生成 `redacted_时间戳` |
| `--mode` | `code` 代号一致化（默认）/ `star` 全遮蔽 / `keep` 保留首尾 |
| `--categories` | 启用类别，逗号分隔；默认除银行卡、企业名称外全部启用；企业名称需另加 `--redact-companies` |
| `--dry-run` | 只扫描并出报告，不写任何输出文件 |
| `--dpi` | 扫描件/图片 OCR 渲染分辨率，默认 300 |
| `--no-ocr` | 禁用 OCR；图片与扫描页将标为失败，不会静默放行 |
| `--keep-embeds` | 保留 PDF 内嵌附件（默认剔除） |
| `--aggressive-names` | 更激进的姓名识别（误报率上升，不建议默认开启） |
| `--overwrite` | 允许覆盖同名输出 |
| `--no-mapping` | 不生成映射表 |
| `--redact-companies` | 脱敏公司、律所、会计师事务所、合伙企业、工厂、商行等企业名称（默认保留） |
| `--redact-institutions` | 脱敏银行、法院、公安等机构名称（默认保留） |
| `--list-categories` | 列出全部类别 |

可用类别：`id_card`（身份证）、`phone`（手机）、`landline`（固话）、`birth`（出生日期）、`email`、`qq`、`wechat`、`passport`、`bankcard`（银行卡）、`uscc`（统一社会信用代码）、`person`（姓名）、`company`（企业名称）、`address`（地址）。

其中 `bankcard` 默认关闭；`company` 需配合 `--redact-companies` 才会生效。

## 四、脱敏呈现（`--mode code`，默认）

同一批次内，同一实体始终使用同一代号，便于文书前后对照。

| 类别 | 示例输出 | 说明 |
|---|---|---|
| 姓名 | 赵某、孙某 | 代号取自固定池，**不使用真实姓氏**；若池中代号与本案真实姓氏相同会自动跳过 |
| 企业名称 | 甲公司、乙公司 | **默认保留**；加 `--redact-companies` 后才脱敏公司、律所、会计师事务所、合伙企业、工厂、商行等 |
| 地址 | 杭州市〔地址已脱敏〕 | 有市级保留到市；只写“省+县”时保留到县；门牌以下全遮 |
| 身份证号 | 330102********1230 | 保留前 6 位（行政区划）和后 4 位 |
| 手机号 | 138****5678 | 保留前 3 后 4 |
| 固定电话 | 0571-******** | 保留区号 |
| 出生日期 | 1985年**月**日 | 保留年份，遮月日 |
| 邮箱 | z***@***.com | 保留首字符与顶级域名 |
| QQ / 微信 | ****** | 全遮 |
| 护照号 | E******** | 保留首字母 |
| 统一社会信用代码 | 91************DEFU | 保留前 2 后 4 |
| 银行卡号 | ************1234 | 保留后 4（需显式启用） |

`star` 模式统一替换为 `***`；`keep` 模式保留首尾字符但不做代号。**三种模式都不保留完整的原始值。**

## 五、识别方式与已知边界

| 类别 | 识别方式 | 主要风险 |
|---|---|---|
| 身份证号 | 18 位正则 + **校验位验证** | 校验位可排除大部分订单号、账号误报 |
| 统一社会信用代码 | 18 位字符 + **校验位验证** | 可靠 |
| 手机号 | 号段正则 + 数字边界 | 可靠 |
| 固定电话 | 区号格式，或“电话/传真”上下文 | 裸 7–8 位数字不处理，避免误伤金额、案号 |
| 出生日期 | “出生/生日/生于”上下文，或“日期+出生”语序 | 合同日期、期限不会被当作生日 |
| 邮箱 / QQ / 微信 / 护照 | 强格式，或标签上下文 | QQ、微信、护照通常需要“QQ：”“微信号：”等标签 |
| 姓名 | 角色词上下文 + 百家姓校验；支持“委托人/受托人”“姓名+律师”；容忍 PDF 提取产生的空格/换行（如“王小 明”“王小↵明”）；判决书落款“审判员/书记员/人民陪审员”逐字换行也可识别；表格中结合表头/角色列 | **无角色词的自由文本裸姓名仍可能漏检**；姓名被拆到**两页**时无法跨页匹配 |
| 企业名称 | **默认不启用**；加 `--redact-companies` 后按组织形式后缀识别，并限制左向扩展（遇数字、标点、金额表述即停） | 简称、字号、无后缀名称可能漏检；银行、法院等机构不在企业范围内，需另加 `--redact-institutions` |
| 地址 | “住址/地址”上下文，或“省+市+区+路+号”结构 | 缺省市区或写法特殊时可能漏检 |

**企业/机构名称默认全部保留。** 包括：公司、律师事务所、会计师事务所、合伙企业、工厂、商行，以及银行、信用社、法院、检察院、公安/派出所、政府机关（人民政府、各类管理局、税务局、民政局、司法局、财政局、教育局、市场监督管理局等）、学校、医院、仲裁委员会、公证处、街道办、居委会、村委会等。

需要脱敏时按需加参数：

```bat
:: 只脱敏企业（公司、律所、会计师事务所、合伙企业、工厂、商行）
redact.bat 文件路径 --redact-companies

:: 只脱敏机构（银行、法院、公安等）
redact.bat 文件路径 --redact-institutions

:: 企业 + 机构都脱敏
redact.bat 文件路径 --redact-companies --redact-institutions
```

单独写 `--categories company` 也会启用企业名称脱敏。

**表格补充规则：** Excel 与 Word 表格中，若表头为“姓名/当事人/法定代表人/联系人”等，或同一行有“原告/被告/甲方”等角色词，则该列/相邻单元格的孤立姓名会被识别。此规则为低置信补充，可能把“杭州”“华为”等两字词误判为姓名，需复核。

**关于 `--aggressive-names`（默认关闭）：**
开启后会额外识别“张伟与李娜”“张伟向李娜”“张伟诉李娜”这类没有角色词的并列姓名，以及与“民间借贷”“合同”“纠纷”等法律名词相邻的姓名。代价是误报率上升（例如“华为与小米”可能被当作姓名）。仅在材料中姓名大量出现在叙述性段落时开启，并加强复核。默认模式下，姓名主要靠“原告/被告/法定代表人/甲方/姓名：”等角色词识别，正式文书通常已足够。

## 六、各格式的处理方式

| 格式 | 处理方式 | 注意事项 |
|---|---|---|
| `.docx` | 直接改写 OOXML，覆盖正文、表格、页眉页脚、文本框、批注、文档属性 | 跨 run 的匹配会把替换值写入首个 run，沿用其格式 |
| `.xlsx` | openpyxl 读写，覆盖单元格、批注、页眉页脚 | 含图表、透视表、宏、图形对象的工作簿会提示人工复核 |
| `.doc` / `.xls` | 调用本机 Word/Excel 转为 docx/xlsx 后处理，**输出为 docx/xlsx** | 转换在临时目录进行，原文件不动；单文件 90 秒超时 |
| PDF（文字版） | PyMuPDF 修订式删除：先删批注，再逐字符定位、**按行分别遮盖**并 `apply_redactions()` | **真删除**，不是覆盖黑块；姓名跨行时分行遮盖，不会把整段文字一起涂黑；不回填代号 |
| PDF（扫描版） | 300dpi 栅格化 → OCR → 整行黑块 → 重建页面 | 失去文字层；文件体积可能增大 |
| PDF（扫描 + OCR 文字层） | 图片覆盖页面 ≥50% 即按扫描页处理，整体栅格化后重建 | 防止“只删文字层、底图仍可见”；原文字层会被丢弃 |
| 图片 | OCR → 整行黑块 → 另存 | 同时丢弃 EXIF；JPEG 质量 95 |

**PDF 的特别说明：** 文字版 PDF 被修订的位置会变成黑块，原文无法复制；扫描版整页重建为图片。两者都不会写入代号文本。若需要保留可读代号，请处理 docx 原件。

PDF 文字层常把姓名拆成“王小 明”“王小↵明”，脚本会按完整姓名匹配；判决书落款的“审↵判↵员↵某某”也能识别。但姓名若被拆到**相邻两页**，仍可能漏检。

## 七、输出物

```
redacted_2026-11-25_1530\
├── 01_诉讼文书\起诉状.docx        ← 保持原目录结构
├── 02_证据\证据清单.xlsx
├── 脱敏报告_2026-11-25_1530.md    ← 可分发
└── 映射表_2026-11-25_1530.json    ← 敏感，勿外传
```

- **脱敏报告**：总体统计、逐文件命中数、警告、失败原因、残余复扫结果。报告本身不含原始值。
- **映射表**：记录“原始值 → 代号”，用于回溯。**含真实个人信息，必须与脱敏件分开存放。**

## 八、人工复核清单

机器处理完后，建议按以下顺序过一遍：

1. 打开报告，确认“失败”与“跳过”清单，逐个处理。
2. 检查“残余复扫”是否有剩余命中。
3. 抽查正文：姓名、地址、身份证、电话是否已替换，代号是否前后一致；如启用了企业/机构脱敏，再核对公司、律所、银行等名称。
4. 检查表格、页眉页脚、文本框、批注。
5. 检查扫描件：黑块是否覆盖完整，是否有漏识别的行。
6. 检查公章、印章、手写签名、图片内嵌文字——这些**不在自动处理范围内**。
7. 检查文件名本身是否含当事人信息（脚本不改文件名）。
8. 判决书等 PDF 重点核对落款（审判员、书记员、陪审员）与跨行姓名是否已遮盖。

## 九、常见问题

**Q：一次拖多个文件没有反应/没有生成文件？**
旧版本只接受一个输入路径，多文件拖拽会触发 `unrecognized arguments` 后直接退出。现已支持多输入，可直接拖多个文件。若仍无输出，请改用命令行把多个路径列出，观察窗口中的报错：

```bat
redact.bat D:\案件\起诉状.docx D:\案件\证据清单.xlsx -o D:\案件\输出
```

**Q：OCR 报错或极慢？**
首次运行需加载模型，约 10–30 秒；之后的图片按页处理。若提示 OCR 引擎不可用，执行：

```bat
.venv-redact\Scripts\python.exe -m pip install rapidocr-onnxruntime
```

**Q：PDF 提示“已加密”？**
先去除打开密码，再处理。脚本不会尝试破解。

**Q：判决书里的姓名被 PDF 拆成两行，会不会漏？**
不会。脚本允许姓名中间出现空格或换行（如“王小 明”“王小↵明”），按完整姓名匹配并分行遮盖；落款“审↵判↵员↵某某”也能识别。但姓名被拆到**相邻两页**时仍可能漏检，需要人工核对当事人栏与落款。

**Q：Word/Excel 转换卡住或弹窗？**
脚本对单文件设 90 秒超时；连续两次失败会自动禁用本批次的 Office 转换。建议先把异常文件手动另存为 docx/xlsx 再跑。

**Q：输出目录里为什么多了 `_1` 后缀？**
目标文件已存在且未加 `--overwrite`，脚本自动改名，避免覆盖。

**Q：能不能处理压缩包？**
不能。`.zip/.rar/.7z` 会被列为跳过，请先解压。

**Q：能不能识别公章上的公司名？**
不做强制识别。印章为图形化文字且常有弧形变形，OCR 识别率低，报告中固定列为人工处理项。

## 十、环境重建

若 `.venv-redact` 损坏或换机：

```bat
cd /d D:\claudedata\.claude\script
python -m venv --system-site-packages .venv-redact
.venv-redact\Scripts\python.exe -m pip install pymupdf rapidocr-onnxruntime
```

`--system-site-packages` 让虚拟环境复用已安装的 python-docx、openpyxl、xlrd、pywin32，无需重复安装。

## 十一、合规提醒

1. 本工具全程本地运行，不上传任何文件；仅 `pip install` 阶段需要联网。
2. 映射表、原始材料、中间转换文件均属敏感信息，请按所内保密要求存放。
3. 脱敏不改变证据的原始性判断；对外提交前仍需核对证据来源、页码、骑缝等要素。
4. 本脚本为初筛工具，不替代律师对材料内容的实质审查。
